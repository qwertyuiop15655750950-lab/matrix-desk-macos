# 小红书矩阵工作台 v2.7.2 · Mac 真机测试清单

目标：验证"连续跑 24～72 小时不会随机崩"。分三个阶段，全部在你的 Mac 上操作。

## 准备

1. 解压 `xhs-matrix-desk-v2.7.2.zip`，终端进入目录
2. `bash setup.sh`（自动装依赖 + Chromium）
3. `./venv/bin/python run.py` 启动（启动时会自动检查环境）

## 阶段一：3 个账号冒烟（约 1 小时）

- [ ] 账号页新增 3 个账号，🌐批量分配代理（一号一 IP，美国住宅）
- [ ] 逐个"启动浏览器" → 扫码登录 → 确认会话保存成功
- [ ] 内容库建 1 条图文草稿 → 发布页新建队列（3 个账号）→ 处理下一个
  - [ ] 每个账号浏览器自动填好内容，你人工点发布
  - [ ] 队列状态变为 finished，发布记录有 3 条
- [ ] 消息页：3 个账号加入监控 → 等一轮轮转 → 确认无报错
- [ ] 「账号」页 → 选中账号 → 「发布页自检」→ 全 ✅
- [ ] 「消息」页 → 「消息页自检」→ 全 ✅
- [ ] 给其中一个账号发条测试私信（用小号）→ 确认工作台收到提醒 → 软件内人工回复一条

**通过标准**：无 `database is locked`、无跨线程报错、浏览器不闪退。
**出问题发回**：`data/logs/app.log` 末尾 50 行 + `data/error_shots/` 截图。

## 阶段二：10 个账号 48 小时连续跑

- [ ] 10 个账号全部扫码登录 + 加入监控
- [ ] 建 1 个 10 账号发布队列，跑完
- [ ] 保持软件开着跑满 48 小时（Mac 不休眠：系统设置 → 电池 → 防止自动睡眠）
- [ ] 每 12 小时看一眼：总览页异常账号数、data/logs/app.log 有无 ERROR

**通过标准**（v2.7.x 验收线）：
- 无 SQLite 线程异常（`SQLite objects created in a thread`）
- 无 `database is locked` 卡死
- 无 BrowserContext 跨线程异常
- 浏览器崩溃后能自动重建（日志里有 `status=rebuilt` 即正常自愈）
- 10 个号的轮转监控、线索、联系方式扫描都正常产出

## 阶段三：扩量决策（10 号稳定后）

- 20 号 → 观察内存（活动监视器，预期 +2～4GB）
- 50 号 → 重点看 Chromium 进程数、轮转一轮耗时
- 100 号 → 确认 6 分片轮转一轮 ≤ 5 分钟

## 常见问题速查

| 现象 | 处理 |
|---|---|
| `Executable doesn't exist` | `python -m playwright install chromium` |
| 扫码登录超时 | 检查该账号代理 IP 是否可用，换 IP 重试 |
| 连续 5 次异常的账号 | 状态卡会提示；先查代理，再查登录态 |
| 发布页自检 ❌ | 把 ❌ 项截图发回，改 `config/selectors.json` 即可 |
| 想看详细日志 | `data/logs/app.log`（结构化：时间 task aid stage status error） |
