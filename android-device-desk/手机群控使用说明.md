# Android 手机群控

手机群控使用 Android Platform Tools 和 scrcpy，通过 ADB 发现已授权设备，独立设备工作台按需操作。截图、投屏与输入等功能需在目标手机逐机验证。

## 连接与查看

1. 在 Android 手机开启开发者选项和 USB 调试，用 USB 连接电脑。
2. 在手机上允许此电脑进行调试，然后进入工作台「手机群控」点击「刷新设备」。
3. 状态为「已连接并授权」的设备可操作。未授权或离线设备会被拒绝，不会自动批准调试权限。
4. 点击某台手机的「截图 / 标记」只获取一张 PNG，不后台持续刷新。
5. 点击「按需投屏」打开此机 scrcpy 窗口。最多同时 2 个窗口，最大尺寸 800 像素、30fps、无音频；关闭投屏会回收工作台自己启动的对应进程。
6. 勾选设备后可点击「检查尺寸 / 横竖屏」，只读取尺寸和当前方向，不开视频流。尺寸或方向不同会提示逐机核对点击位置；它不表示不同应用布局中的控件位置相同。

未连接手机时，不会自动启动投屏或模拟已有设备。每条设备操作明确指定设备序号，失败设备不会阻止批次内其他设备继续。

## 批量操作与浏览计划

勾选设备后可上滑、下滑、左右滑动、返回或进入主页。截图上标记的批量点击位置按屏幕比例应用于勾选设备；执行前应确认各手机页面和方向适合该位置。

多天浏览计划在「浏览计划」中配置。手机任务仅在用户已打开的当前内容页停留并间隔滑动，不自动点赞、关注或发消息。计时使用实际活跃等待秒数，暂停不计时，停止后终止后续滑动。执行中的手机拒绝新的批量操作、草稿准备和发送请求；查看截图仍可用。需要手动操作时先停止该手机的计划。

## 中文输入助手

普通 adb 输入支持基础英文、数字和标点。中文、emoji、换行及其他字符使用官方 [ADBKeyBoard](https://github.com/senzhk/ADBKeyBoard) 的 UTF-8 Base64 广播输入。

1. 点击目标手机的「安装中文输入助手」，明确安装已下载的官方 APK。
2. 点击「手机输入法设置」，在手机上人工启用并选择 **ADB Keyboard** 为当前输入法。
3. 点击「检查中文输入」，确认助手已安装且为当前输入法。
4. 输入完成后可在手机切回常用输入法。

工作台不会自动启用、切换或替换手机当前输入法。未启用助手时，中文草稿返回明确错误，不会尝试不支持的输入或把输入失败标为成功。请自行从官方仓库获取 APK 并核验来源，具体机型仍需验证。

## 填稿、预览与发送

1. 在各手机人工打开目标聊天，点击输入框并保持键盘状态；再用「截图 / 标记」取当前截图。
2. 为每台手机分别标记输入框和发送按钮，填写聊天页顶部显示的完整联系人或群聊名称。
3. 勾选设备，填写文案，点击「填入草稿并取预览」。这一步只填稿，不发送；已有草稿不会被覆盖。
4. 检查每台手机返回的截图，核对聊天对象和文案。只有已验证的成功草稿进入下一步。
5. 点击明确的「发送已预览草稿」才执行发送按钮点击。此时重新核对设备在线、屏幕方向、聊天标识、输入内容、焦点和按钮位置。预览 5 分钟失效；状态变化会阻止发送。

发送结果表示经过验证的按钮已被点击；实际是否送达、是否被应用阻止，须在手机确认。无法暴露可验证输入框、聊天标识或发送按钮的应用，不支持自动发送，可通过投屏人工处理。完成测试前请先用自有测试聊天验证。

## 已验证范围

后端与 UI 的模拟测试覆盖设备序号隔离、未授权/离线拒绝、失败继续、草稿不自动发送、中文助手能力检测、Unicode Base64 编码、预览过期和聊天状态变化阻止发送、投屏上限、进程回收、浏览计时与停止、手机任务占用、导航切换和 UI 错误处理。测试没有对真实手机执行发送。
